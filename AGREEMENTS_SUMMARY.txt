FEATURE DETAILS
================================================================================

DYNAMIC SWITCHING:
  - User selects "Buyer/Renter" → Buyer agreement shows
  - User selects "Associate/Seller" → Associate agreement shows
  - User changes selection → Agreements reset and switch automatically
  - No page refresh needed

FORM VALIDATION:
  - Error if trying to submit without checking agreements
  - Error message: "You must accept all agreements to continue"
  - Form prevents submission until all agreements accepted
  - Validation happens client-side before API call

LINK HANDLING:
  - Click agreement title to open full document
  - Opens in new browser tab (preserves form state)
  - External link icon shown next to title
  - Link click doesn't close/clear the form

RESPONSIVE DESIGN:
  - Works on desktop and mobile
  - Checkboxes stack vertically
  - Links are clickable and readable on small screens
  - No layout issues or overflow

KEY TECHNICAL DETAILS
================================================================================

STATE MANAGEMENT:
  agreementAccepted: Record<string, boolean>
  Structure: { "buyer-agreement": false, "associate-agreement": false, ... }
  Updated via: onAgreementChange(agreementId, accepted)
  Reset on: User type change

VALIDATION LOGIC:
  1. Check if agreements exist for user type
  2. If yes, verify all are accepted (all values = true)
  3. Show error if any are unchecked
  4. Prevent form submission

API INTEGRATION:
  - No API changes needed
  - Agreements are client-side validation only
  - Backend receives same registration data as before

STYLING FRAMEWORK:
  - Uses shadcn/ui Checkbox component
  - Tailwind CSS classes
  - Follows existing form styling patterns
  - Responsive using Tailwind breakpoints
